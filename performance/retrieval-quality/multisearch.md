## Production trace

`server/src/services/workspace-chat.ts:1066` selects MCP agent only when actor, enabled MCP env, API key and no narrowing filters are present. Thus a retrieval-only or filtered request cannot measure this agent loop. Agent mode appears as debug `mode: retrieval`; verify actual tool activities instead of trusting that mode label.

`chat-mcp-agent.ts` exposes MCP catalog tools, asks for workspace search and inline citation indices, uses six model steps with final-step tool choice none, 120-second timeout, zero retries and at most 4096 output tokens per step. It records actual per-step provider usage through the scoped usage recorder. `chat-mcp-tools.ts` enforces 12 invocations per turn, fixes workspace scope, collects up to 80 evidence entries, truncates returned result JSON at 40,000 characters and citation text at 1500 characters. These truncations may hide a decisive qualifier or premise; the original citation object survives but the agent may never see its full evidence.

The ordinary retrieval chat path passes query decomposition, rewrite, iterative multi-hop and contextual compression settings to search, then takes only six final citations. Those retrieval operations are not evidence that the assistant itself performed two search tool calls. `workspace.search-many` and nested `workspace.chat` also do not satisfy the frozen two-call metric.

Generic improvements worth separately testing: instructions to identify missing premises, search for an entity/key learned from first evidence, distinguish explicit fact from deduction, cite each premise and abstain when contradictory or underspecified. Avoid forcing extra searches for simple facts. Consider bounded full-passage access when tool evidence truncation hides a condition. Do not add corpus-specific prompts or value recognizers.

## What the scorer proves

It checks required answer patterns, forbidden patterns where supplied, abstention language for negative controls, page/document identity of every inline marker, all gold premise pages actually referenced inline, successful search activity counts and the 12-call bound. It rejects a correct number with one uncited premise, invalid pages, failed searches and nested/batched-search substitutes. `node --test scripts/multisearch-quality/score.test.mjs` runs adversarial offline checks plus gold-free/no-retry transport checks.

This is deterministic screening, not a semantic judge: an answer can include both a correct phrase and an unsupported claim. Independent review must verify that every material claim follows from the cited text, arithmetic is explained, ambiguous entities are not silently collapsed, conflicting versions are not arbitrarily resolved and abstention is substantive. A pass cannot be promoted as complete hallucination detection. Add semantic labels only in evaluation gold; never production code. No quality result is established until actual source ingestion, server runs, independent semantic review and integrity gate pass.

## Prompt experiment and authenticated API boundary

The isolated prompt experiment adds general instructions to search for missing premises using learned identifiers, distinguish explicit statements from deductions, cite each premise, and avoid resolving absent/ambiguous/conflicting evidence by assumption. It changes neither budgets nor tools. A real SDK offline test scripts two distinct searches, verifies first-hop evidence reaches the second model turn and second-hop evidence reaches the answer turn, retains both citation pages and checks three model usage records. This proves loop plumbing; a scripted model cannot prove prompt adherence or quality improvement. Focused agent/tools tests: 9 passed. No paid semantic measurement yet.

Do not add `actor` blindly to the public chat handler. Both routers permit validated API-key actors through declared authentication middleware, and native search/MCP enforce search scope and workspace access. But MCP `workspace.chat` dispatches to the same native search `/chat` handler. Passing actor there unconditionally would allow nested MCP agents, each with fresh step/tool budgets. A safe future integration should pass the authenticated actor at the outer API boundary while explicitly forcing nested `workspace.chat` into grounded retrieval-only mode. Validate recursion prevention, scope/workspace denials and usage attribution before enabling it. This experiment makes no auth/route changes.

External `integrity-manifest.json` files wrap unchanged authored source and gold with SHA-256 hashes and provenance for both splits. The unchanged independent integrity judge passed both (six cases each, zero findings), comparing against `a0f4cc0`; sanitized reports are `integrity-development.json` and `integrity-heldout.json` in the external evidence directory. A first restricted invocation failed because Node could not spawn Git (`EPERM`); rerunning the same gate with permitted Git subprocess access passed. Rerun after final integration before promotion.
