# Persist paid search usage when retrieval fails

Independent review of the new BGE query route found that actual usage was buffered before vector validation, but malformed output threw before the only successful-search finalizer could persist that buffer. Paid usage could disappear from attribution. The same failure shape affects strategy/retrieval exceptions, including suppressed child searches whose parent never adopts their events.

The search journal now exposes a serialized usage-only flush that stamps its existing organization, workspace and session scope without writing a successful search/results row. The runner flushes before returning, including suppressed child searches, and on failure. Existing deterministic event IDs and ledger flush progress keep subsequent flush/adoption idempotent. A failed persistence attempt is reported through error telemetry while the original retrieval error is rethrown; a database outage remains an accounting failure, not a claim that the event was stored.

Behavioral validation uses a paid-usage callback followed by actual BGE vector validation failure, checks one scoped usage insertion, confirms no vector retrieval occurred, and verifies an additional flush makes no duplicate insertion. Both ordinary and suppressed result-session modes are covered. Another test makes storage fail and checks the original vector error survives with the storage failure reported. Four focused suites (journal/failure/search service/MMR): 45 passed. Broad integration checks remain with the coordinator.

Separate independent review of `33738b0` and `f0ce310` found no blocking issue: vectorless MMR preserves highest relevance and ranked search results retain the strongest prefix before chat/result caps. These changes do not implement semantic MMR or demonstrate a corpus-wide gain. Embedding-screen review initially blocked hardcoded standard privacy and implicit OpenAI retries; its owner added live ownership/privacy checks per batch, actual-mode propagation, explicit zero retries and exact original provider-input-key checks for all 13,675 frozen chunks. Candidate vectors stay in isolated local per-arm maps/files; production document indexes are not rewritten. Final exact ledger reconciliation and independent result scoring are still required before promotion. This review does not independently approve the reviewer's own chat changes.
