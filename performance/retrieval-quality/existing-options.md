# Existing retrieval controls: readiness audit

Inspected current local source; no new paid calls or production edits. These are implemented controls, not measured proof of improved retrieval. The cheapest meaningful first comparisons are local rerank on/off, parent context on/off and result count. Query rewrite, HyDE, stepback and bounded iterative retrieval already exist and can be screened before building a replacement.

## Exact configuration surfaces

Workspace settings: `PATCH /:workspaceId/search-settings` on the workspaces router, body `{ "retrievalDefaults": { ... } }`; corresponding GET returns settings. Schema lives in `packages/shared/src/workspace.ts`. Direct search accepts the public keys below, mapped by `server/src/lib/search-input.ts` to internal options. Omitted flags inherit workspace defaults. Do not send internal names such as `useHyDE` to the strict public search schema.

| Capability | Workspace `retrievalDefaults` key (default) | Direct-search request key | Readiness and likely use/failure |
|---|---|---|---|
| Query rewrite | `queryRewrite` (false) | `queryRewrite` | Implemented, opt-in; one hosted call, 100 output-token cap. Clarifies vague language; can drift away from a precise identifier. Changes semantic query; lexical query remains original plus synonyms. |
| Hypothetical answer embedding | `useHyDE` (false) | `hyde` | Implemented, opt-in; one hosted call, 150 output-token cap. Embeds generated neutral answer-like passage; useful for semantic mismatch, risks invented associations. Lexical branch still uses original query. |
| Generalized second search | `stepback` (false) | `stepback` | Implemented, opt-in; hosted generalization up to 100 output tokens, searches original and generalized queries then fuses. Useful for conceptual mismatch; can dilute precise terms and increase work. |
| Decomposition | `queryDecompose` (false) | `queryDecompose` | Implemented local regex splitting on and/vs/compare/difference between/also, each surviving part at least three words. Parallel subsearches and fusion. Useful for explicit compound questions; not semantic planning and will miss implicit multi-hop dependencies. No explicit subquery-count cap in splitter. |
| Iterative multi-hop | `iterativeMultiHop` (false) | `iterativeMultiHop` | Implemented, opt-in; up to three search hops, repeated-query/empty-result stop. Hosted bridge entity extraction between hops, up to 220 output tokens; reads first six chunks, 1200 chars each. No key: heading-path fallback. Useful for learned identifiers; can miss bridges outside truncated evidence. |
| Rerank | `useRerank` (true) | `rerank` | Implemented LOCAL BM25 with candidate-corpus IDF and adjacent-term bonus; up to 200 fused candidates. No model/API fee. Useful for literal phrases buried by fusion; lexical emphasis can demote valid paraphrases. `rerankRemote` is a stub that also returns BM25, not a neural reranker. |
| Diversity | `useMmr` (false), `mmrLambda` (0.4) | `mmr`, `mmrLambda` | Implemented but production call passes no vectors. Actual behavior is position-based resampling: even rank positions then reversed odd positions. Lambda has no effect on this fallback. Do not claim semantic MMR or tune lambda expecting an effect. |
| Parent context | `parentRetrieval` (true) | `parentRetrieval` | Implemented: attaches full stored page as `parentText`; missing page text falls back to bounded neighboring chunks (24 chunks / 30,000 chars). Can recover nearby definitions/qualifiers after a hit; does not recover an absent candidate. Check answer consumer actually uses parent text. |
| Context compression | `useContextualCompression` (false) | `compression` | Implemented, opt-in; up to 20 parallel hosted calls, 1024 output tokens each, before final selection. Accepts only an extracted contiguous substring after whitespace normalization, otherwise keeps source. Can reduce context noise; may drop qualifiers/premises. Not a missing-candidate fix. Claimed 60–80% reduction in source comment is not established by this audit. |
| Result count | `resultCount` (8; max 50) | `limit` (1–100) | Implemented; increases recall/inspection and downstream context cost. Direct retrieval chat clamps retrieval to 4–12 and retains six citations, so it is not equivalent to direct-search limit. |
| Relevance floor | `minScore` (unset) | `minScore` (0–1, zero disables) | Implemented; otherwise environment `SEARCH_MIN_SCORE`. Removes low raw-relevance candidates before rerank. Lowering may recover dropped evidence but can increase false positives. Preserve negative controls. |
| Graph context | `enableGraphExpansion`, `enableCommunityExpansion`, `graphHops` (unset) | `graphExpansion`, `communityExpansion`, `graphHops` | Implemented; unset derives graph features from indexed pipeline config. Needs existing entity/community artifacts. Not an instant fix on an index that never built them. Workspace hops 1–3; public direct-search schema accepts 1–4. |

## Hybrid weights and missing controls

`server/src/search/rrf.ts` uses equal-list reciprocal rank fusion with default k=60. Neither public search schema nor workspace retrieval defaults exposes vector/text blend weights, branch-specific weights or fusion k. Workspace `boosts.any`, `boosts.byMime`, pinned results and ranking controls act on retrieved results; they are not vector-versus-lexical weights. A neural/cross-encoder reranker and semantic decomposition planner are missing implementations, even though local rerank and heuristic decomposition are available. Avoid introducing either before existing controls are measured.

Recursive planning precedence is decomposition, then stepback, then iterative multi-hop (`session-planner.ts`). Enabled modes can survive into child searches because each branch disables itself only. Turning all enhancements on can multiply calls; evaluate one mechanism at a time. Rewrite runs before HyDE in ordinary preparation; text retrieval keeps original query expanded by glossary. Enhancements use `SEARCH_OPENROUTER_MODEL = resolveApiTextModelDefault()`, not necessarily the requested chat answer model. Verify actual route/pricing and scoped usage before paid screening. Missing key or failed provider call generally falls back, so configured true is not proof that enhancement ran.

## Chat and assistant activation

Per-request `retrieval` in chat accepts ONLY `resultCount`, `useHyDE`, `useRerank`, `useMmr`, `mmrLambda`, `iterativeMultiHop`, `enableGraphExpansion`, `enableCommunityExpansion`, `graphHops`. It does not accept rewrite, decomposition, stepback, compression, parent context or minScore; configure workspace defaults or use direct search for those comparisons. Saved conversation overrides merge above workspace defaults and request overrides above conversation values. Natural-language configuration only changes result count/rerank/MMR/lambda for that thread.

The MCP assistant loop is default-enabled by `DOCSLURP_CHAT_MCP_ENABLED` (config default true), but additionally requires actor, hosted key and no document/type/tag/date narrowing filters. At the audited baseline, app workspace-chat passed actor while `workspaceChatHandler` in `routes/search.ts` did not, so that public nonstream chat path could not activate this loop. The subsequent bounded-entrypoint experiment below corrects this boundary. Do not infer agent mode from `debug.mode`, which remains `retrieval`. Verify actual successful `debug.toolCalls`.

The loop already allows repeated `workspace.search`, six model steps (last tools disabled), 12 total tool invocations, 120 seconds, zero retries and capped output. Search-many batches up to 20 independent queries (concurrency max four), but one batch is not two actual assistant search-tool calls. Ordinary search `iterativeMultiHop` is an internal retrieval chain, also distinct from repeated assistant calls. MCP tools read workspace defaults; merged conversation retrieval overrides are described in agent instructions rather than forcibly applied to each dispatched search. Thus request override activation must be verified in raw tool/search journals before calling an experiment controlled.

## Existing verification and next experiment

Relevant existing tests: `search-session.test.ts` covers journal inheritance, preserving reranker winner through context positioning and decomposed recursive calls; `search-service.test.ts` covers parent context/fallback, bridge chain and compression usage; `search-strategy-usage.test.ts` checks actual strategy recording; `search-controls.test.ts` covers settings controls; `search-routes.test.ts` covers strict transport/mapping; `chat-search-options.test.ts` checks conversation scope; `rerank.test.ts` tests local ranking; `chat-mcp-tools.test.ts` / `chat-mcp-agent.test.ts` exercise tool accounting and behavior. These are code-path evidence, not heldout quality evidence. This report-only change did not rerun suites.

Coordinate with ranking diagnosis: establish whether desired evidence exists in candidate pools and whether floor, fusion, BM25, positional diversity or context positioning loses it. First compare current baseline with `rerank:false`, then controlled result-depth and parent-context changes, preserving prior successes. If evidence is semantically absent, test rewrite or HyDE separately; if two premises require a learned key, test iterative retrieval and assistant repeated search separately. Compression comes after adequate premise recall and must retain all cited qualifiers. No paid experiments were executed by this audit.

## Bounded public-agent entrypoint experiment

Public native chat (streaming and nonstreaming) and OpenAI-compatible chat now pass their authenticated actor, abort signal and internal `allowAgentTools:true` to `chatWorkspace`. Existing search-scope, organization and workspace checks remain in the route. MCP `workspace.chat` uses a dedicated internal grounded router that supplies the same actor but `allowAgentTools:false` and `allowConfiguration:false`, preventing nested agents from refreshing the outer loop budget. The internal flag is absent from the strict public schema; callers cannot supply it. Verified tests exercise trusted API-key forwarding, missing-scope 403, excluded-workspace 404, public flag rejection, nested MCP grounded permission, and service execution with permission on/off. Prompt-quality improvement remains unmeasured until real model evaluation.
