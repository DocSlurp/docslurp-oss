# Optional CPU image orientation

Conservative quarter-turn normalization is enabled by default (`DOCSLURP_IMAGE_ORIENTATION=true`). Set `false` to disable it; legacy `1`/`0` values remain supported. It runs only through an image orientation provider plugin (`imageOrientation` in [extractor plugins](extraction/extractor-plugins.md)) that decodes pixels inside an isolated VM; without one, orientation is off. There is no local decoder fallback when the provider or its model is unavailable.

The shared detector runs on vision page/region inputs and embedded PDF images a VM extractor returned. Original assets remain unchanged. Corrected embedded images are separate PNG derivatives linked to their originals, with the decision in the media map; vision decisions are persisted in successful page details. EXIF transforms are applied once and alpha is preserved. Linked masks and their associated images are skipped together.

The [official PaddleOCR document orientation model](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/module_usage/doc_img_orientation_classification.en.md), PP-LCNet_x1_0_doc_ori, has approximately 7 MB of weights and four classes (0, 90, 180, 270 degrees). Build-time conversion uses the Apache-2.0 [PaddlePaddle model repository](https://huggingface.co/PaddlePaddle/PP-LCNet_x1_0_doc_ori) pinned at `d3b95a6dff5fe8a94f2748e12b61cb26818a0df8`. Source hashes and converted-model hash are recorded in the baked manifest. Paddle is absent from the runtime; ONNX Runtime runs with one CPU thread.

Correction requires confidence >=0.90, margin >=0.50, and a second upright classification after rotation. Tiny, low-contrast, extreme-aspect and ambiguous images abstain. These are conservative policy thresholds, not calibrated probabilities. PNG/JPEG/WebP only; animated images, inputs above 32 MB or 16 million pixels are refused. The provider must keep resource limits and give the VM no credentials or network. Customer pixels are decoded only inside its VM.

Each image is one provider call. Compute usage, including failed jobs, is recorded in the scoped ledger. Vision admission precedes preprocessing. At most 64 orientation attempts are allowed per run state, including failed attempts, shared across both paths. After the allowance is exhausted, originals continue through ingestion with `skipped-limit` metadata and no further orientation calls; the count is saved with run stats at checkpoints. This allowance is not an exactly-once monetary budget: a crash before a checkpoint may replay attempts. Infrastructure compute is not customer-billable spend, so the customer credit cap alone does not bound it.

This first integration does not change PDF vector/text rotation, native OCR-only paths, arbitrary skew, or linked-mask composition. A broader held-out false-rotation study and remote startup/cost measurements remain outstanding; the default was enabled at the operator’s explicit request.
